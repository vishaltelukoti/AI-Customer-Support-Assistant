# Day 6: similar-ticket retrieval

## Scope

Day 6 implements local similar-ticket retrieval only. It does not add FastAPI endpoints, RAG answer generation, LangGraph agents, vector database servers, cloud embeddings, OpenAI embeddings, or Pinecone.

No API key is required for the local Sentence Transformer + FAISS retrieval implementation.

## Corpus and leakage controls

The source is `data/processed/historical_tickets.csv`, generated by the existing preprocessing pipeline. The FAISS index includes only rows where `split == "train"`:

- indexed training tickets: 11,436
- validation tickets indexed: 0
- test tickets indexed: 0

Embeddings are generated from `ticket_text` only. Answers are saved as result metadata for future RAG, but answer text is not used to build document embeddings or query embeddings. Validation/test tickets are used only as evaluation queries and are never added to the index.

## Model and index

The embedding model is `sentence-transformers/all-MiniLM-L6-v2`, a public local Sentence Transformer checkpoint. It was chosen because it is small, CPU-friendly, requires no external API call at inference time, and produces general-purpose sentence embeddings suitable for a POC retrieval baseline.

The index uses normalized 384-dimensional embeddings and FAISS `IndexFlatIP`, so inner product is cosine similarity after normalization. Default Top-K is 3.

Saved metadata maps each FAISS position to:

- `ticket_id`
- `ticket_text`
- `category`
- `priority`
- `answer`
- `source_record`
- `version`
- `language`
- `split`
- `type`
- tags

## Artifacts

Artifacts are written to `experiments/retrieval/`:

- `tickets.faiss`
- `metadata.jsonl`
- `retrieval_config.json`
- `retrieval_evaluation.json`
- `retrieval_evaluation.md`

The saved index was loaded from disk and searched successfully.

## Evaluation

Evaluation uses a fixed lightweight subset: 250 validation tickets and 250 test tickets. A retrieved ticket is relevant when it has the same category as the held-out query ticket. Category labels are used only for evaluation, not for embedding or retrieval.

| Metric | Value |
| --- | ---: |
| Recall@1 | 0.656000 |
| Recall@3 | 0.764000 |
| Recall@5 | 0.844000 |
| MRR | 0.722500 |

Leakage checks in `retrieval_evaluation.json` confirm that validation/test IDs were not indexed, answers were not used for embeddings, and self-retrieval was not observed.

## Limitations

The corpus and answers are synthetic. Same-category retrieval is a coarse proxy for usefulness; it does not prove that retrieved answers are correct or safe to reuse. The index is exact and local, suitable for this POC size but not designed as production infrastructure. No reranking, query expansion, deduplication beyond existing preprocessing, answer generation, citation formatting, or API integration is included.
